效果（也称指令，Commands）用于在特定作用域内动态影响游戏。它们是对游戏当前状态的一次性改动，无法产生持久影响。与之相对，修正 用于对游戏状态施加可量化的持续、永久影响。效果块不能直接施加修正，但可以添加能够施加修正的东西，最常见的是通过 add_ideas。

效果在游戏中用于众多作用域，最常见的可编辑效果块是 国策奖励、事件选项 和 决议效果。

请注意，某些效果可以从变量取值，即 add_manpower = var:my_var 这在效果参数中由 <variable> 标明。有关变量效果的信息，请参见变量。

效果列表可能已经过时。完整但未排序的效果列表可在 /Hearts of Iron IV/documentation/effects_documentation.html 或 /Hearts of Iron IV/documentation/effects_documentation.md 中找到。

作用域

主条目：作用域

Scopes serve as special effect types that modify the entity that serves as the context for the effects being executed, such as GER = { add_political_power = 150 } adding 150 political power to  德国.

效果作用域

这些只能作为效果使用；把它们当作 触发器 使用将不会产生任何效果。

流程控制

这些作用域在效果作用域内使用，以控制效果的执行。

if 语句

if 语句允许仅在满足某些 触发器 时才执行效果。条件语句用 if = { ... } 效果表示。if 语句内部的 limit = { ... } 充当 trigger block，定义何时应执行，而 if = { ... } 内直接包含的其他所有内容都会被解释为条件为真时应执行的效果。

例如，若该国拥有正向 政治点数 且稳定度低于 90%，以下内容将为其增加 10% 稳定度：

if = {
    limit = {
        has_political_power > 0
        stability < 0.9
    }
    add_stability = 0.1
}

若不满足限制条件，则内部的所有效果都不会执行。若满足，则每一个都会执行。若省略限制条件，则默认为始终为 true。

效果必须位于 if 语句内部才能与限制条件相关联。例如，无论游玩哪个国家，这都将始终给予 100 政治点数：

if = {
    limit = { tag = BHR }
}                         # Closes if = { ... }. Since no effects are inside, this means that the if statement does absolutely nothing
add_political_power = 100 # Outside of if = { ... }, so it will always give 100 political power, even if not playing as BHR

可选地，可以添加 else_if = { ... }（limit = { ... } 的作用类似）和 else = { ... }。若 if = { ... } 中的初始限制为 false，则继续检查下一个 else_if = { ... } 的限制。若那里的限制为 false，则继续下一个，直到遇到结尾或 else = { ... }。存在两种变体：嵌套与非嵌套。在第一种情况下，else_if 或 else 直接放在前面的 if 或 else_if 内部，而在第二种情况下它被放在 right after。若出现重叠，优先使用非嵌套的 if 语句。以下是使用非嵌套 if 语句的示例：

if = {
    limit = {
        stability < 0.3 # If stability is below 30%, add 30%.
    }
    add_stability = 0.3
}
else_if = {
    limit = {
        stability < 0.6 # Otherwise, if it's below 60% (i.e. 30-59%), add 20%
    }
    add_stability = 0.2
}
else = {
    add_stability = 0.1 # If there's 60-100% stability, add 10%
}

在提示框中，只显示将会执行的效果。未满足的 if 语句内的效果（或因 if 语句已满足而未被读取的 else/else_if）将对玩家隐藏，触发器也会被隐藏。为避免玩家困惑，custom effect tooltips can be used to tell the player what this effect block would do，例如在 else 中使用时。

随机效果

如果你希望某个效果有随机概率被执行，否则什么也不发生，random = { ... } 块是实现这一点的最简单方式：

random = {
    chance = 80
    add_stability = 0.4
    add_war_support = 0.3
}

这特别意味着有 80% 的概率增加 40% 稳定度和 30% 战争支持度，相应地有 20% 的概率什么也不做。此处的概率采用 0 到 100 的标度。

如果你希望游戏在多个效果块之间选择，可以改用 random_list。例如，若你希望某个效果随机给予玩家四种加成之一，你可以按如下方式编写：

random_list = {
    10 = {
        add_stability = 0.5
    }
    10 = {
        add_manpower = 10000
    }
    10 = {
        add_war_support = 0.5
    }
    10 = {
        army_experience = 100
    }
}

该数字不是概率，而是每个选项的权重，因为它们不必总和为 100 或任何数字。例如，权重为 20 的选项被选中的可能性是权重为 10 的选项的两倍。总体而言，某个选项被选中的概率等于该选项的权重除以所有权重之和。

也可以使用修正（类似 MTTH 块）来影响每个可能随机效果的权重，或使用变量作为概率。

random_list = {
    30 = {
        modifier = {
            factor = 1.3
            has_country_flag = inward_perfect_flag
        }
        add_stability = 0.5
    }
    25 = {
        add_manpower = 10000
    }
    20 = {
        add_war_support = 0.5
    }
    my_variable = { # Taking "my_variable" as the variable's name, both "var:my_variable" and "my_variable" are valid options, left up to the developer's preference.
        army_experience = 100
    }
}

若设置了国家标记 inward_perfect_flag，它会将上述 30 的概率乘以 1.3 得到 39。同时，my_variable 将取相应临时变量的值或当前作用域的变量作为该选项的权重。

请注意，如果你想创建一个包含随机列表的可重复决议，默认情况下同一决议在游戏中每次被触发时都会选取相同的随机结果。你可以通过在决议块中包含以下行来反转此行为：

fixed_random_seed = no

这仅用于决议。在其他地方，随机种子默认是不固定的，因此无需把此参数设为 "no"。

提示框操作

另见：本地化文件

The "tooltip" in this case refers to the text shown to the player in-game that explains what the effect block changes within the game, such as "+50 政治点数".

在效果块内有 3 种编辑提示框的方式：

  • hidden_effect = { ... } 用于把其中的效果从提示框中隐藏，使其执行不会向玩家显示。
  • effect_tooltip = { ... } 则用于把效果放入提示框中而不实际执行它们。
  • custom_effect_tooltip = my_localisation_key is used in order to put an arbitrary paragraph of text as an effect that will get executed.

例如，这个示例 焦点的完成奖励 同时使用了全部三种：

completion_reward = { 
    hidden_effect = {
        every_subject_country = { country_event = my_event.1 }
    }
    custom_effect_tooltip = send_event_to_subjects_tt
    effect_tooltip = {
        add_political_power = 100
    }
    custom_effect_tooltip = reject_war_tt
}

在此情况下，send_event_to_subjects_tt 和 reject_war_tt 是在任意以 UTF-8-BOM 编码的 /Hearts of Iron IV/localisation/english/*_l_english.yml 文件中定义的本地化键，假定语言为英语。

 send_event_to_subjects_tt: "Sends a demand to our every subject.\nIf they agree, we get the following for each subject:"
 reject_war_tt: "If they reject the demand, we gain a wargoal against them."

在游戏中，这会显示为：

效果：

向我们每个附属国发送一项要求。若他们同意，我们每个附属国都会获得以下内容：政治点数：+100 若他们拒绝该要求，我们将获得针对他们的战争目标。

值得注意的是，触发国家事件的效果会从提示框中隐藏。完成该焦点后，唯一发生的事情是每个附属国都会收到一个 ID 为 my_event.1 的事件，该国不会立即获得 100 政治点数。

元效果

元效果允许你把非动态效果（不接受修正、只能使用静态标记或常量值的效果）当作接受变量来使用。

add_equipment_to_stockpile = {
    type = infantry_equipment_2
    amount = eq_amount
}

在上面显示的效果中，添加的装备数量是动态的，可以使用变量 "eq_amount" 设置。然而，此效果不允许你把变量用作装备类型。你不能把 "infantry_equipment_2" 存入变量并在此处使用。

However, meta effects will let you use variables and scripted localization within them to build effects as if they were texts and run them. Let's make previous effect accept equipment type and equipment level as variables stored in "eq_type" and "eq_level". 

set_variable = { eq_type = 1 } # Sets the equipment type to "1", which determines the equipment given using scripted localisation, included below
set_variable = { eq_amount = 10 } # Sets the amount of equipment given to 10
set_variable = { eq_level = 2 } # Sets the equipment level to 2, which is used directly in the meta effect, no scripted localisation required

meta_effect = { # The actual meta effect. This can go anywhere you need it: in a decision, in a scripted effect, in a scripted GUI click effect, etc...
    text = {
        add_equipment_to_stockpile = {
            type = [EQ_TYPE]_[EQ_LEVEL]
            amount = eq_amount
        }
    }
    EQ_LEVEL = "[?eq_level|.0]" # Gets the "eq_level" variable and saves it as "EQ_LEVEL" for the meta effect to use
    EQ_TYPE = "[This.GetEquipmentName]" # Gets the equipment type from scripted localisation, included below, based on the "eq_type" variable, and saves it as "EQ_TYPE" for the meta effect to use
}

# The scripted localization for the "eq_type" variable, which goes in a scripted localisation file
defined_text = { # Since the "eq_type" variable in this example is equal to 1, the equipment given by the effect is "artillery_equipment"
    name = GetEquipmentName
    text = {
        trigger = {
            check_variable = { eq_type = 0 }
        }
        localization_key = "infantry_equipment"
    }
    text = {
        trigger = {
            check_variable = { eq_type = 1 }
        }
        localization_key = "artillery_equipment"
    }
}

如你所见，我们创建了一个接受两个参数的 meta_effect。这些参数将用于替换元效果内部的 [EQ_TYPE] 和 [EQ_LEVEL]。EQ_LEVEL 将被替换为 [?eq_level|.0]，即 eq_level 的整数值（在此情况下 2.000 变为 2）。EQ_TYPE 稍复杂一些，它被替换为一段脚本本地化。该脚本本地化会检查 eq_type 变量，并根据其值返回装备的键标记。若为 0，将返回 "infantry_equipment"。若为 1，将返回 "artillery_equipment"。

因此最终结果是 [EQ_TYPE] 被替换为 "artillery_equipment"，[EQ_LEVEL] 被替换为 "2"，最终我们的效果将被构建为：

add_equipment_to_stockpile = {
    type = artillery_equipment_2
    amount = eq_amount
}

这将给予你 10 个 artillery_equipment_2。

可以向元效果添加 debug = yes。这将在效果执行时把最终效果打印到 game.log，使调试更容易。

脚本化效果

脚本效果的作用与函数类似，它们可以在 /Hearts of Iron IV/common/scripted_effects/*.txt 中定义，然后在其他地方作为简写形式使用。脚本效果永远不会自行运行 并且需要在其他地方作为效果使用才能执行。此外，游戏允许创建自定义控制台指令，它们也是脚本效果。

脚本效果的定义很简单，就是

scripted_effect_name = {
	<effects>
}

此示例可以在常规代码中作为 scripted_effect_name = yes 效果使用。

脚本效果可以在控制台中通过输入 e scripted_effect_name 来访问并运行。

要创建自定义控制台指令，脚本效果名称应以 d_ 开头。控制台指令本身不包含 d_，因此 d_test_command 在控制台中将作为 test_command 运行。在自定义控制台指令中，运行该指令的国家为 FROM，而 ROOT 为选定的国家、州或人物。在控制台指令之后输入的、以空格分隔的内容（如 test_command 123 321 GER）会被添加到 'args' 临时数组中。以下是一个脚本效果示例，它会把作为参数输入的每个州转交给运行该控制台指令的国家

d_transfer_states = {
	for_each_scope_loop = {
		array = args
		FROM = {
			transfer_state = PREV
		}
	}
}
