修正本质上是一个用于内部计算的变量。不过，与定义文件不同，修正可以在任何修正块中动态改变。一般而言，修正用于创建一种稳定、持久且易于撤销的效果。每个修正的写法都完全相同：modifier_name = 0.1。这会把指定的数值加到该修正在其所应用作用域上的总数值中。[a] 例如，假设没有其他修正改变该国的这项数值，那么对该国（可能位于不同的修正块中）应用political_power_gain = 0.2和political_power_gain = -0.05，会使政治点数增益在基础增益之上总共增加+0.15。由于修正的工作方式，值为 0 的修正永远不会有任何效果。 这也意味着负向修正总是会生效，并且效果与正向修正相反。修正当前的总数值可以通过读取modifier@modifier_name作为变量获取，例如set_variable = { my_var = modifier@political_power_gain }。这对国家和州都适用，但对单位指挥官则改用unit_modifier@modifier_name和leader_modifier@modifier_name。

以下这些是不修正，尽管它们看起来很相似：

  • 研究加成，用于为某个特定科技类别提供增益。这其实属于理念中的一个参数，可以以相同方式用于顾问，但不能用于其他地方。
  • 装备加成，例如降低建造某个装备原型的成本。同样，这属于理念中的一个参数，可以以相同方式用于顾问和国家领袖特质，但不能用于其他地方。
  • 关系修正，可用于改变国家之间的好感度（包括贸易影响力），定义于/Hearts of Iron IV/common/opinion_modifiers/*.txt文件中。

应用修正

应用修正的方式多种多样，但以下是主要的几种：

  • 理念——主要包括但不限于国家精神和隐藏理念。这是为一个国家添加修正最简单的方式的方式是使用效果块（例如国策奖励）、使用add_ideas或add_timed_idea。这些只对国家级作用域有效。
  • 动态修正——这与理念类似（在国家界面上显示在同一屏幕中），但它们接受变量，也可以应用于州和单位指挥官。这是为一个州添加修正的主要方式。
  • 特质：
    • 国家领导人特质——这些可以添加到理念（包括功能类似的顾问）和国家领袖上，从而对国家生效。
    • 单位指挥官特质——这些可以添加到单位指挥官上，并对指挥官本人或其部队生效。这是为单位指挥官添加修正的主要方式。
  • 静态修正:
    • 全局修正——这些修正何时生效完全是硬编码的，例如用于稳定度和战争支持度加成的那些。不过，它们什么作用的内容是可以修改的。
    • 省份修正——这是向特定省份施加修正的主要、甚至唯一方式。
    • 关系修正——这是在不需在定向修正块中指定具体国家 tag 的情况下，把一个定向修正从一个国家施加到另一个国家的唯一方式。

每个修正都遵循相同的结构，即被赋予一个数值，例如在许多支持修正的代码块中采用如下写法支持修正的，就像上面列出的任何一项那样：

modifier = { # While this is present in, for example, ideas or decisions, it's equally likely to see is modifier = { ... } being omitted entirely in other entries, such as country leader traits.
    political_power_gain = 0.1
    disabled_ideas = 1
}

任何修正都不能取非数值，包括必须为 1 才有效果的布尔型修正。请注意修正不支持 if 语句。最接近的替代品是动态修正，它们允许使用变量。

提示框修改

修正块内部支持hidden_modifier = { ... }块，用于阻止其中的修正显示在提示框中。此外，还可以用custom_modifier_tooltip = localisation_key_tt添加一条自定义本地化字符串，作为其中一项修正显示在本地化文本中。两者结合后看起来如下：

modifier = {
    hidden_modifier = {
        political_power_gain = 0.1
    }
    custom_modifier_tooltip = political_power_gain_tt
}

自定义修正现在支持动态命令（方括号内的任何内容）。此前它们只能用于非动态本地化文本

动态修正

如果你想给一个国家施加一个稳定一致的修正，改用理念会更简单。

动态修正定义在/Hearts of Iron IV/common/dynamic_modifiers/*.txt文件中，是一种可接受变量的修正类型。修正每天更新一次，除非使用force_update_dynamic_modifier 效果强制刷新修正的影响。它们既可应用于国家也可应用于州，对于后者，变量必须为州定义，而不是为国家所有者或控制者定义。它们也可以应用于单位指挥官。

与理念不同，无法通过调试模式或控制台没有任何办法重新加载动态修正的定义，对其定义的任何改动都需要重启游戏才能在游戏中生效。此外，由于变量检查每天刷新，它们的优化程度不如理念。因此在不需要为国家作用域的动态修正使用变量时，既更简单也更高效的做法是改用国家精神。

动态修正会按每个作用域每天进行一次求值。该过程包含以下步骤：

  • 每天开始时，每个动态修正的每个变量修正值都会被临时重置为 0，即使使用了空值合并运算符来假定一个不同的默认值。常量值不会被重置。
  • 随后动态修正会按照它们通过add_dynamic_modifier赋予作用域的顺序依次求值。
  • 在动态修正内部的每个变量都被计算出来之前，其中的变量值都被视为 0。这包括那些依赖其他修正的值，其中也包括modifier@modifier_name游戏变量，或使用该游戏变量的 MTTH 变量。
  • 在单个动态修正的变量计算完成之后，修正会随该动态修正一并应用到作用域上，随后游戏继续处理添加到当前作用域的下一个动态修正，直到每个动态修正都计算完毕。

参数

  • icon决定动态修正使用哪个图标。该图标使用任意/Hearts of Iron IV/interface/*.gfx文件中定义的精灵图。如果未指定图标，它将被隐藏。
  • enable准确决定动态修正的修正何时生效。如果动态修正已设置，但它所设置到的国家或州不满足要求，其效果就不会生效。可选。
  • remove_trigger会在触发器满足时自动移除该动态修正。可选。
  • attacker_modifier若在州作用域的动态修正中设为 true，会额外使该修正作用于这样一些师：它们虽然不在带有该动态修正的州内，但正在攻击位于该州的敌军。可选，默认为 false。

修正会作为列表直接放在动态修正内部。非修正类的理念属性（例如equipment_bonus或research_bonus）无法在动态修正内部使用。

示例

dynamic_modifier_name = {
    icon = GFX_idea_unknown
    enable = { always = yes }
    remove_trigger = {
        NOT = {
            has_variable = var_name
        }
    }
    political_power_gain = var_name # Variable value
    weekly_manpower = 1000 # Constant value
    stability_factor = GER.stability_var # Checks specifically GER's variable, regardless of where the modifier is applied
}

添加动态修正

动态修正通过add_dynamic_modifier 效果添加。一次典型的动态修正添加如下所示：

add_dynamic_modifier = { modifier = dynamic_modifier_name }

由于动态修正没有指定的作用域，同一个修正既可以赋给国家、州、单位指挥官，也可以同时赋给其中若干个——这完全由add_dynamic_modifier效果在何处执行决定。

在界面中，动态修正若可见会占据以下位置：

  • 对于国家，动态修正会显示在国家精神列表中，排在常规精神之后。
  • 对于州，动态修正会显示在dynamic_modifiers_grid中，位于选中州视图底部的专属区域内，在/Hearts of Iron IV/interface/countrystateview.gui里标记。

添加动态修正时，也可以让它具有时限，或让它使用不同的作用域作为变量的基准。例如，以下代码会把 dynamic_modifier_name 施加给 GER 持续 30 天，但变量会从 POL 上读取：

GER = {
    add_dynamic_modifier = {
        modifier = dynamic_modifier_name
        scope = POL  # The modifier itself will be applied to GER, but the variables will be read off POL.
        days = 30
    }
}

具体来说，假设 dynamic_modifier_name 是前面示例中创建的那个动态修正，如果你执行set_variable = { POL.var_name = 0.3 }，那么作为该效果结果赋给 GER 的动态修正将提供每天 0.3 的政治点数增益。不过，如果该动态修正把变量作用域切到 ROOT，写成political_power_gain = ROOT.var_name，那么就应该执行set_variable = { GER.var_name = 0.3 }。

动态修正通过remove_dynamic_modifier移除，写法与 add_dynamic_modifier 类似：remove_dynamic_modifier = { modifier = dynamic_modifier_name }。如果在添加时该动态修正被指定了作用域，那么在移除时也必须指定该作用域。

使用变量的修正不会显示在 add_dynamic_modifier 的提示框中，而那些被设为固定数值的则会显示。虽然这可能使动态修正在只阅读提示框时看起来失效，但一旦真正添加后其实并非如此。在这种情况下，该效果的提示框可以修改，配合添加该动态修正的效果被隐藏。

静态修正

静态修正存储在/Hearts of Iron IV/common/modifiers/*.txt文件中，其中每个代码块都是一个修正块，其名称即该静态修正的 ID。静态修正有 5 个主要类别：

全局修正

全局修正由硬编码的游戏功能施加。它们的名称不得更改，因为代码在内部使用它们，但它们的效果可以编辑。全局修正的例子包括非核心州的惩罚，以及稳定度和战争支持度的效果。

难度修正

这些在/Hearts of Iron IV/common/difficulty_settings/*.txt文件中施加。用于在游戏规则菜单中于游戏开始时强化特定国家。如果没有定义任何难度设置，该菜单将无法打开。每个难度设置都定义为一个difficulty_setting = { ... }块，且必须位于一个总括性的difficulty_settings = { ... }块中。难度设置可以包含以下参数：

  • key = localisation_key是本地化键，用作难度设置在游戏规则菜单中显示的名称／
  • modifier = static_modifier设定该难度设置要使用的静态修正。
  • countries = { ... }是一个以空白分隔的国家 tag 列表，表示该难度设置适用于哪些国家。
  • multiplier = 2.0是静态修正在最大值时乘以的数值。由于每条难度规则有 5 个等级（包括 0），该数值会被四等分到各等级：第二级为四分之一，第三级为一半，第四级为四分之三。

难度设置文件的一个示例如下：

difficulty_settings = {
    difficulty_setting = {
        key = difficulty_weaken_GER
        modifier = weaken_country
        countries = { GER }
        multiplier = 2.0
    }
    difficulty_setting = {
        key = difficulty_weaken_SOV
        modifier = weaken_country
        countries = { SOV UKR BLR }
        multiplier = 2.0
    }
}

关系修正

不要与关系修正混淆。关系修正会把一个定向修正从一个国家施加到另一个国家，并在触发器满足时自动移除。ROOT 是被施加修正的国家，FROM 则是目标。一个例子如下：

test_relation_modifier = {
	valid_relation_trigger = {
		FROM = {
			has_government = ROOT		# same ruling party as ROOT
		}
	}
	compliance_gain = 0.2				# FROM's states have 20% more compliance gain when controlled by ROOT
}

它们可以通过 add_relation_modifier 效果添加，用法如下：

add_relation_modifier = {
	target = TAG
	modifier = test_relation_modifier
}

remove_relation_modifier 用法类似，可用于移除它们。

省份修正

省份修正把修正施加到特定省份而不是州。它们可以通过 add_province_modifier 效果添加，并用 remove_province_modifier 移除。关于如何使用它们的更多信息可参阅效果页面。一个定义示例如下

mod_modifier = { 
	army_speed_factor = -0.5
	army_defence_factor = 0.5
	dig_in_speed_factor = 0.5
}

许多州作用域的修正也同样适用于省份作用域。为了在界面中生成 GFX，你首先需要编辑/Hearts of Iron IV/interface/countrystateview.gui。该图标必须像其他示例那样定义在 custom_icon_container 内部。一个定义示例如下

iconType = {
	name = "<modifier name>_icon"
	spriteType = "GFX_modifiers_<modifier name>_icon"
	position = { x = 0 y = 0 }
	Orientation = "UPPER_LEFT"			
}

你定义的 spriteType 需要以类似于此示例的方式在/Hearts of Iron IV/interface/*.gfx中定义：

spriteType = {
	name = "GFX_modifiers_<modifier name>_icon"
	textureFile = "gfx/interface/modifiers_<modifier name>_icon.dds"
}

力量平衡修正

力量平衡修正通常自身包含power_balance_daily和／或power_balance_weekly修正，以逐渐把力量平衡倾向某一方。例如，

my_bop_modifier = {
    power_balance_weekly = -0.01 # Changes by 1% each week to the left, in the range of -1 to 1.
}

力量平衡修正通过add_power_balance_modifier 效果添加，如下所示：

add_power_balance_modifier = {
    id = my_bop    # The ID of the balance of power
    modifier = my_bop_modifier # The modifier to add
}

可以用相同语法的remove_power_balance_modifier 效果，或用remove_all_power_balance_modifiers把这些修正从国家上移除。

修正定义

修正定义允许创建一个自定义修正，在你想使用它时可以作为变量访问。定义之后，它完全像一个新变量那样运作，可以用相同的modifier@modifier_name流程作为变量读取。默认情况下它不会有任何效果，只是作为一种通过修正块以加算方式改变该变量数值的手段。每个修正记号都在/Hearts of Iron IV/common/modifier_definitions/*.txt文件中定义为一个独立的代码块，代码块的名称即该修正定义的 ID。它内部可以包含以下参数：

  • color_type = good决定修正数值本身的颜色。共有三个取值：good、bad和neutral。neutral永远是黄色，而good会把正值显示为绿色、负值显示为红色。bad则与good相反。
  • value_type = percentage 决定该数字在提示框中显示的方式。此参数可以设置为以下值：
    • number会显示修正的确切数值。0.02 会显示为“Modifier definition: 0.02”。
    • percentage会让修正以 0 到 1 为刻度的百分比显示。0.2 会显示为“Modifier token: 20%”。
    • percentage_in_hundred会让修正以 0 到 100 为刻度的百分比显示。10 会显示为“Modifier token: 10%”。
    • yes_no以布尔值显示：任何大于 1 的数值都显示为yes，而 0 显示为no。
  • precision = 1决定提示框中在小数点后显示几位数字。例如，如果设为 1，提示框会把 0.341 显示得如同 0.3。请注意游戏本身不支持超过 3 位小数，因此该值不能大于 3。
  • postfix决定在提示框中修正数值之后附加什么内容。允许的取值为 'none'（默认）、'days'、'hours' 和 'daily'。
  • 类别决定该修正的类别。默认类别为 'all'，即属于每一个类别。某些提示框只会显示属于特定类别的修正。可以为同一个修正定义设置多个类别，只需把它们依次定义即可。
允许的取值为 'none'、'all'、'country'、'state'、'unit_leader'、'army'、'naval'、'air'、'peace'、'politics'、'ai'、'defensive'、'aggressive'、'war_production'、'military_advancements'、'military_equipment'、'autonomy'、'government_in_exile' 和 'intelligence_agency'。

修正定义的 ID 也被用作本地化键，以便根据当前开启的语言更改该修正的名称。

示例

modifier_definition_example = {
	color_type = good
	value_type = number
	precision = 1
	postfix = daily
	
	category = country
	category = state
}
modifier_definition_example_2 = {
    color_type = bad
    value_type = percentage
}

在变量中使用

修正定义的作用是改变某个游戏变量的数值，而该变量可以被其他变量读取。你可以通过执行set_variable = { var_name = modifier@modifier_token_name }，把某个变量设为等于当前作用域中同一修正记号所有数值之和。这个示例会把 var_name 设为等于 modifier_token_name 的总数值。

请注意，与国家、州不同，单位指挥官在其作用域中使用的是 leader_modifier@modifier_definition_name 或 unit_modifier@modifier_definition_name。

让某个修正记号每月在随机的核心州中创建民用工厂的用法示例，可放在任意 on action 文件中：

示例
on_actions = {
    on_monthly = {
        effect = {
            if = {
                limit = {
                    check_variable = { modifier@modifier_definition_example > 0 }
                }
                for_loop_effect = {
                    start = 0
                    end = modifier@modifier_definition_example
                    random_owned_controlled_state = {
                        limit = {
                            is_core_of = ROOT
                            free_building_slots = {
                                building = industrial_complex
                                size > 0
                                include_locked = no
                            }
                        }
                        add_building_construction = {
                            type = industrial_complex
                            level = 1
                            instant_build = yes
                        }
                    }
                }
            }
        }
    }
}


关系修正

尽管名字如此，关系修正与修正本身毫无关系，它们用于改变两个国家之间的外交或经济关系。

关系修正在任何/Hearts of Iron IV/common/opinion_modifiers/*.txt文件中作为opinion_modifiers = { ... }块里的一项创建，该项的名称即该关系修正的 ID。如果存在多个 ID 相同的项，则以根据文件名和文件内顺序在更晚时求值的那一项优先，这意味着在 mod 中永远不需要复制基础游戏的文件。

关系修正中会用到以下属性：

  • trade = yes用于决定该关系修正改变的是外交关系还是两国之间的贸易好感度。若未设置，默认为 false，即外交关系。
  • value = -10是该修正的数值，决定关系修正被添加后外交或贸易好感度应改变多少。
  • decay = 1详细说明该关系修正每月趋向零的速度。可选；若未设置，默认为该修正不变化。
  • days = 10 | months = 2 | years = 1决定该关系修正自动移除之前应持续多久。一个月被解释为恰好 30 天，一年为 365 天。可选；若都未设置，该修正将永久存在。
  • min_trust = 10 | max_trust = -10详细说明该关系修正可以变化到的最小值和最大值。由于改变现有关系修正数值的唯一非硬编码方式是通过衰减，这可用于限制其适用幅度。

本地化创建于任意/Hearts of Iron IV/localisation/english/*_l_english.yml文件中，使用带字节顺序标记的 UTF-8 编码（即 UTF-8-BOM），其本地化键即该修正的名称。

示例

在一个新的/Hearts of Iron IV/common/opinion_modifiers/*.txt文件中：

opinion_modifiers = {
    test_trade_modifier = {
        trade = yes
        value = -100    # Provides -100 trade opinion for 2 months
        months = 2
    }
    test_diplomatic_modifier = {
        value = 20      # Provides +20 diplomatic opinion that decays by 0.5 per month
        decay = 0.5
    }
}

在一个新的/Hearts of Iron IV/localisation/english/*_l_english.yml文件中：

l_english:
 test_trade_modifier: "Testing trade modifier"
 test_diplomatic_modifier: "Testing diplomatic modifier"

实现

新的关系修正只能通过在任意效果块中使用add_opinion_modifier 效果（或类似的reverse_add_opinion_modifier）来添加，例如焦点奖励、国家历史文件或理念的on_add 与 on_remove。同样，已施加的新关系修正也只能用remove_opinion_modifier移除。使用add_opinion_modifier施加关系修正时，只有执行该效果的国家会改变其对目标国的好感度。

无法用修正块直接施加关系修正，但可以在修正块效果生效的同时添加或移除关系修正来模拟。例如，这个国家精神会模拟对每一个拥有该理念的其他国家施加关系修正：

使用关系修正的国家精神示例代码
ideas = { country = { idea_opinion_modifier = { on_add = { # 注意：如果该理念是在国家历史或书签的效果中添加的，则不会生效。every_other_country = { # 如果在国家历史中添加，则也要在那里复制这些效果。limit = { has_idea = idea_opinion_modifier } add_opinion_modifier = { target = ROOT modifier = test_diplomatic_modifier } reverse_add_opinion_modifier = { target = ROOT modifier = test_diplomatic_modifier } } } on_remove = { every_other_country = { limit = { has_idea = idea_opinion_modifier } remove_opinion_modifier = { target = ROOT modifier = test_diplomatic_modifier } ROOT = { remove_opinion_modifier = { target = PREV modifier = test_diplomatic_modifier } } } } modifier = { custom_modifier_tooltip = add_opinion_modifier_tt # 因为 on_add/on_remove 不会显示给玩家 } } } }

这些修正属于定向修正，意味着它们必须用在定向修正块中而不是普通修正块中。这包括理念、特质、顾问和决议中的targeted_modifier = { ... }，以及关系修正。targeted_modifier块的结构如下：

targeted_modifier = {
    tag = FROM    # this can also take a variable that stores a scope
    attack_bonus_against = 0.1
    defense_bonus_against = 0.1
}

理念、顾问和决议中的这是一个与modifier = { ... }完全独立的块；因此把它放进modifier = { ... }中不会生效。
